01 · DESIGN

设计取舍：可交付、可解释、可撤销

EgressScope 选择用户态本地代理，而不是内核透明重定向：不需要驱动签名，失败模式清晰，所有系统变更都能撤销。代价也很明确——应用必须遵循代理设置并信任本地 CA，否则内容不可见。

这个选择不追求“看见一切”，而是把能看见的部分做完整，把看不见的部分写清楚。风险分、可见性等级和旁路候选都用于辅助人工判断，不作为自动处置结论。

为什么本地代理

修改系统代理前先备份，退出时恢复；检测到 PAC 脚本时拒绝接管；已有回环代理自动串联，避免接管后断网。

为什么 mitmproxy

不重复实现 TLS 与 HTTP/2。成熟的开源代理负责协议与流式转发，项目集中做归因、策略、证据与产品边界。

为什么本地 CA

内容还原必须由应用信任的 CA 签发站点证书。CA 只安装到当前用户且不自动安装，私钥留在本机数据目录，可随时移除。

技术路径内容可见性部署与维护覆盖面
本地代理 + 本地 CA 本版高：正文、协议语义与进程中低：用户态、无驱动签名中：需应用遵循代理并信任 CA
WFP / WinDivert 透明重定向中：仍受 TLS 固定与信任限制高：驱动、签名与兼容性较高：不依赖应用代理设置
Agent 会话 / MCP 旁路高：可读会话内容低：只读本地数据窄：只覆盖特定 Agent
浏览器扩展中：仅浏览器内请求低：无需系统权限窄：桌面 Agent 与 CLI 不可见
ETW / 内核文件审计不提供内容高：需要管理员与规则工程广：网络与文件系统事件
透明重定向与 ETW / SACL 已列入路线图；本版只覆盖代理路径与旁路元数据。
没有被假装看见的流量：不遵循代理设置的应用不会出现在内容记录里；它们最多以直连候选的形式出现在旁路观测中。
02 · PIPELINE

数据路径：从请求到证据

只有进入本地代理的连接才可能产生内容级记录。每条记录沿五个阶段生成，最终写入本机 SQLite 证据库。

STEP 01

应用发起请求

Agent、编辑器插件、SDK 或桌面程序发出 HTTPS 请求。

STEP 02

进入本地代理

只监听 127.0.0.1，通过系统代理或环境变量接入，不接触局域网。

STEP 03

本地 CA 终止 TLS

签发站点证书，还原 HTTP 语义后重新加密转发。

STEP 04

归因到进程

客户端端口匹配 TCP 表，得到 PID、父链与创建时间。

STEP 05

策略与证据

端点分类、DLP 规则、风险分与处置，正文加密写入哈希链。

03 · ATTRIBUTION

进程归因：把连接落到具体进程

归因只使用本机连接表，不读取任何 Agent 的私有会话文件，也不依赖特定 Agent 的数据格式。

attribution.flowWindows / Linux
client ephemeral port
  → TCP owner table (GetExtendedTcpTable / /proc/net/tcp)
  → PID + process creation time
  → parent process chain
  → redacted command line
  • 连接表匹配：用客户端临时端口查询本机 TCP 归属表，得到发起连接的 PID。
  • 降低 PID 复用误判：缓存 PID 与进程创建时间；PID 被复用时不会把旧进程的记录算到新进程头上。
  • 上下文：保留父进程链与脱敏命令行，用于区分 shell、编辑器、插件宿主与子进程。
  • 平台差异：macOS 非 root 下无法读取 TCP 归属表，记录会降级为不含 PID 的流量。
  • 范围：当前面向登录用户进程；Windows 服务与 SYSTEM 会话的完整归因仍在路线图中。
04 · VISIBILITY

可见性与边界：每条流量都有等级

“代理已启动”不等于“全部可见”。每条流量都带有一个可见性等级和原因；CONNECT 隧道失败与 TLS 握手失败只保留元数据，不伪装成完整记录。

等级含义典型情况
完整本地代理读取并保存了响应正文，仍受单条体积上限约束。信任本地 CA 且未启用证书固定的 HTTPS 请求。
部分正文缺失、被截断、流式未保留，或 WebSocket 消息正文未持久化。WebSocket 握手成功；响应体超限；旧版本记录迁移。
仅元数据只记录连接元数据与失败原因，没有请求或响应内容。CONNECT 隧道失败；TLS 握手失败，可能是证书固定、mTLS 或客户端拒绝本地 CA。
已阻断策略命中，请求在本地被拒绝并记录原因。风险分达到阻断阈值且显式开启阻断。
错误代理或上游错误，未收到响应。上游不可达、代理异常或连接被重置。
旧记录不会回填不存在的正文；仅元数据不等于内容可见，更不等于已拦截。
在配合路径上可以看见
  • 经过本地代理的 HTTP/HTTPS 元数据与正文，受体积上限约束
  • 信任本地 CA 且未启用证书固定的 TLS 1.2 / 1.3 流量
  • PID、父进程链、脱敏命令行与进程创建时间
  • AI 服务分类、模型名、token 用量与 DLP 规则信号
  • 五级可见性与失败原因
  • 直连、QUIC 与 DNS 目标元数据（仅候选）
不承诺、也看不到
  • 证书固定、mTLS 与双向证书校验
  • QUIC / HTTP3 的内容级解析与解密
  • 绕过代理的直连内容
  • 未实现的 WFP / WinDivert 透明重定向
  • Windows 服务 / SYSTEM 会话的完整归因
  • 完整文件读取历史（只有句柄抽样）
05 · NETWATCH

旁路观测：检测，不重定向

netwatch 每 15 秒读取本机连接表，用来提示“可能没走代理”的连接。它不参与内容审计，也不改变流量路径。

信号触发条件能说明什么
direct_tcp公网 TCP 80 / 443 / 8080 / 8443直连候选，可能是未遵循代理的应用，也可能是上游或非 HTTP 协议。
quicUDP 443可能是 QUIC / HTTP3；不解密、不拦截，无法给出内容级结论。
dnsUDP / TCP 53；TCP 853DNS 目标；不记录查询内容，Windows 解析缓存只用于 IP→域名。
只观测公网地址；回环、私网与链路本地地址会被忽略。
  • 去重与上限：同一目标 10 分钟内去重，单次扫描最多 50 条、单日最多 5000 条。
  • 归因：复用现有 PID 归因，能显示候选连接的发起进程。
  • 暂停：暂停采集会同时暂停旁路观测。
  • 候选不等于证据：连接可能存在并不代表内容已经外发；需要结合代理记录、进程行为与其他证据判断。
没有拦截、重定向、驱动或 QUIC 解密。WFP / WinDivert 透明重定向仍未实现；当前版本不会强制接管不遵循代理的应用。
06 · FAIL-SAFE

断网保护：接管系统代理之后，本机不能失联

最危险的失败模式不是“看不到”，而是程序退出后系统代理仍指向 127.0.0.1 上已经停止的端口，浏览器和多数应用无法联网。v0.4.0 用四层机制处理它。

1

关机 / 注销时优雅恢复

程序在独立消息线程上创建隐藏的顶层窗口，注册 WM_QUERYENDSESSION / WM_ENDSESSION；恢复期间用 ShutdownBlockReasonCreate 让系统显示等待原因，写回启用前的代理备份并刷新 WinINET 后立即释放。

AUTOMATIC · 无需配置
2

启动时校正

启动时检查系统代理是否仍指向本工具：端口变了就改指新的监听端口；本地代理没启动就恢复原始设置，不把机器留在断网状态。

AUTOMATIC · 无需配置
3

独立看门狗任务

启用系统代理时默认勾选注册一个仅当前用户的计划任务：登录时以及每 2 分钟检查，代理指向已停止的回环端口时，等待 30 秒宽限后恢复备份并自动停用。

每用户 · 不需要管理员
4

手动恢复

桌面控制台提供“恢复系统代理”，也可以直接运行独立恢复器；极端情况下仍可在 Windows 设置的网络代理页手动关闭。

MANUAL · 始终可用
PowerShell恢复与自愈
# 恢复启用系统代理前的原始设置
EgressScope.exe --restore-proxy

# 仅当代理指向本工具且端口已停止时恢复
EgressScope.exe --recover-proxy --recover-grace 30

# 注册或移除当前用户的登录自启
EgressScope.exe --enable-autostart
EgressScope.exe --disable-autostart

# 程序移动或覆盖更新后，把自启与看门狗改指当前 exe

集成自愈：启动时以及运行中每 10 分钟核对当前用户的 Run 键与看门狗计划任务；程序被移动、覆盖安装或更新后自动改指当前 exe，不会覆盖其他程序的自启项。
真实边界：仓库提供 tools/shutdown_lab.ps1 实验脚本，包含 prepare / verify 与需要显式确认的重启选项；但本版本未在 CI 或真实虚拟机中执行真实关机 / 重启。契约测试只验证 Windows 会话结束回调能触发恢复，不能替代真实关机验证。
诚实的限制：优雅恢复依赖系统把会话结束消息投递给我们。直接拔电源、内核崩溃或强制结束进程时收不到通知，恢复发生在下一次登录后（启动校正 + 看门狗）。看门狗与开机自启只覆盖当前登录用户；Linux 与 macOS 版本不修改系统代理，也不写 Run 键。
07 · SHIPMENT

安装与更新：按当前用户交付

Windows x64 安装器使用 Inno Setup，按当前用户安装，不申请管理员权限。卸载会撤销系统集成，但默认保留审计数据。

安装器

  • 固定目录：安装到 %LOCALAPPDATA%\Programs\EgressScope，可选桌面快捷方式；开始菜单提供主程序与“恢复系统代理”入口。
  • 卸载：移除开机自启并恢复系统代理；静默卸载保留数据；交互式卸载会先询问是否删除 %LOCALAPPDATA%\EgressScope，默认保留。
  • 签名状态：当前构建未签名，SmartScreen 可能提示未知发布者；CI 提供可选签名钩子，配置密钥后才会签名。

自动更新

  • 节奏：启动约 30 秒后首次检查，之后每 24 小时一次，结果缓存 6 小时；可在设置中关闭。
  • 来源：只访问 GitHub Releases；仅接受 HTTPS 与 GitHub 域名，安装包必须通过 SHA-256 校验。
  • 范围：只有 Windows x64 且发布页同时提供安装器与校验文件时才允许自动安装；ARM64、Linux 与 macOS 需手动下载。
  • 安装：使用 /SILENT /NORESTART /CLOSEAPPLICATIONS 启动安装器；应用先恢复系统代理并退出。

08 · DATA SAFETY

数据安全：审计工具不应成为新的泄露面

数据边界落实在密钥位置、导出格式、默认设置与系统变更的撤销路径上，而不只是一句“本地优先”。

正文加密

AES-256-GCM 加密请求与响应正文，主密钥由当前用户的 DPAPI 保护；更换用户或拷走数据库都无法直接解密。

默认脱敏

列表、搜索、预览与 JSONL 导出只包含脱敏内容与哈希；原始正文需二次确认才解密，且不回写数据库。

最小系统变更

CA 只装当前用户且不自动安装；系统代理修改前备份，检测到 PAC 时拒绝接管；退出时仅在设置仍属于本工具时恢复。

回环服务

Web 审计台只绑定 127.0.0.1，每次启动生成随机令牌，校验 Host 头并应用严格 CSP。

证据链

每条记录的关键摘要与上一条哈希链接；可随时校验链条完整性，并以 JSONL 格式导出脱敏证据。

文件触达

只抽样近期外发进程打开的文件句柄，记录路径与时间等元数据，从不读取文件内容。

10 · LIMITS

已知限制

这些限制不是待办清单的托词，而是当前版本的真实能力边界。选择工具前请先确认它们与你的场景不冲突。

  • 加密边界：证书固定、mTLS、应用层端到端加密与 QUIC 内容不可见；本项目不尝试攻破它们。
  • 流量入口：未经过代理的直连内容不可见；没有 WFP / WinDivert 透明重定向，也不安装内核驱动。
  • 系统范围：Windows 服务与 SYSTEM 会话不在完整归因范围；文件触达只有句柄抽样，不覆盖已关闭句柄。
  • 验证范围：未执行真实关机 / 重启验证；ARM64 Tk 与托盘未实机验收。
  • 交付范围：当前构建未签名；Windows SmartScreen 与 macOS Gatekeeper 可能提示未知发布者。
  • 平台差异：macOS 非 root 下没有 PID；macOS 与 Linux 无托盘、无系统代理接管。
使用前提：只在你拥有或已获得明确书面授权的设备上使用。不要在存有真实凭据的日常主机上分析疑似恶意软件；受信 CA 会扩大本机可被中间人解密的范围，请在隔离虚拟机或快照中处理，结束后移除 CA。
11 · FAQ

技术问答

这里回答实现与交付细节；产品层面的问题可以在首页常见问题中查看。

01安装器和自动更新安全吗？构建签名了吗？
Windows x64 安装器按当前用户安装，不需要管理员权限；卸载会恢复系统代理与开机自启。更新只访问 GitHub Releases，安装包必须通过 SHA-256 校验才会静默安装。当前构建未签名，SmartScreen 可能提示未知发布者；请从官方发布页下载并核对校验值。SHA-256 只能确认下载内容与发布页一致，不等同于发布者身份验证。
02关闭窗口会退出吗？托盘能做什么？
Windows 上关闭控制窗口会隐藏到通知区域，不会退出；托盘菜单可打开控制台与审计台、暂停或恢复采集、退出并恢复系统代理。登录自启默认隐藏启动；--no-tray 时关闭窗口即退出。托盘仅 Windows 提供，macOS 与 Linux 没有托盘；Windows x64 已做人工冒烟测试，ARM64 的 Tk / 托盘界面尚未验证。
03“检测，不重定向”是什么意思？直连和 QUIC 被拦截了吗？
这是检测能力，不是拦截能力。v0.4.0 每 15 秒读取本机连接表与 Windows 解析缓存，记录直连 TCP 80/443/8080/8443、UDP 443 QUIC 候选与 DNS 目标，不记录查询内容。没有拦截、重定向、驱动或 QUIC 解密；候选只说明连接可能存在，不代表内容已经外发。暂停采集会同时暂停观测，WFP / WinDivert 透明重定向仍未实现。
04这些功能做过真实关机或重启验证吗？
没有做过真实虚拟机关机 / 重启验证。仓库提供 tools/shutdown_lab.ps1 实验脚本，包含 prepare / verify 与需要显式确认的重启选项，但本版本未在 CI 或真实虚拟机中执行真实关机 / 重启；契约测试只覆盖 Windows 会话结束回调。
05修改设置需要重启程序吗？开机自启能关吗？
采集开关、阻断阈值、保留期、文件句柄抽样、上游代理、自动更新检查与开机自启都是热更新：控制台改完立即生效，直接编辑 config.json 也会在 2 秒内被运行中的进程采纳，接口返回 config_reload 告诉你哪些键已生效。只有监听端口、Web 端口与证书目录这类需要重建进程的字段要重启一次。开机自启默认开启，可在控制台一键关闭或运行 --disable-autostart。
06已经在用 Clash 或其他本地代理怎么办？
启动时会自动继承本机回环 HTTP 代理（例如 127.0.0.1:7890）并串联转发，避免接管后断网。上游只看到重新加密后的 TLS 字节。带用户名密码的上游、PAC 脚本与 SOCKS 目前不支持，这些场景请改用单 Agent 环境变量接入。
