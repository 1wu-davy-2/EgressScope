01 / 盲区

问题不在模型，
而在看不见的出站路径。

当 Agent 获得文件系统、终端和代码库的访问权，它同时获得了把这些上下文送出本机的能力。传统安全工具关心连接是否存在，却很少回答：是谁、在什么时候、把什么内容、送到了哪里。

01 / CONTEXT

Agent 自动装载上下文

工作区文件、终端输出、环境变量和密钥可能在一次会话里被装入提示词。会话日志能告诉你会话内容，却不能证明这些内容是否、何时、向何处发生了外发。

02 / ENCRYPTION

HTTPS 让异常失去内容

流氓软件、被劫持的编辑器插件与合法 Agent 使用同一条加密通道。流量面板只显示字节数；没有应用配合与本地 TLS 终止，你无法判断上传的是遥测、代码，还是客户数据。

03 / ATTRIBUTION

连接不等于发起者

日志里的一条 POST /v1/chat 没有意义，如果不知道它来自哪个进程、哪条父进程链。没有归因，风险告警只会变成噪声；有了归因，才能定位到具体工具与工作流。

“

真正的空白不是“有没有网络监控”，而是网络元数据与内容、进程、文件线索之间缺少一条连续的证据链。EgressScope 选择在这条链上做工程，而不是再做一个流量计数器。

02 / 架构取舍

本地代理 + 本地 CA +
进程归因，是最可落地的组合。

我们比较了透明重定向、浏览器扩展、Agent 会话旁路和内核级采集。最终选择用户态本地代理作为第一版主干：它不要求驱动签名，不依赖某个 Agent 的私有格式，能在应用配合时还原内容，也允许用户清楚知道审计边界在哪里。

应用 / Agent

Claude Code、Codex、编辑器、SDK 或普通桌面程序发起 HTTPS 请求。

本地转发代理

仅监听 127.0.0.1。系统代理或进程环境变量把流量引到这里，不影响局域网。

TLS 终止

使用当前用户信任的本地 CA，对应用配合的 TLS 1.2 / 1.3 连接还原 HTTP 语义。

进程归因

客户端临时端口匹配本机 TCP 表，缓存 PID + 创建时间，避免 PID 复用误判。

策略与证据

端点分类、DLP 信号、风险分；正文加密、审计链、脱敏预览与策略处置。

进程流量→ 内容可读→ 是谁发起→ 可验证证据→ 本机审计台
WHY LOCAL PROXY

失败模式清晰。应用不配合，就看不到；不会假装全量可见。系统代理修改前备份，退出时尝试恢复。已有 Clash 等回环代理时自动串联，避免接管后断网。

WHY MITMPROXY

不重复造 TLS。成熟的开源代理负责 HTTP/2、证书签发与流式转发，项目把精力放在归因、策略与证据链。

WHY LOCAL CA

内容需要应用同意。CA 只安装到当前用户信任根，且不会自动安装；固定证书、mTLS、E2EE 不被攻破。

03 / 审计结果

从“有一条连接”，到
“这一次外发是什么”。

审计结果不是要制造恐慌，而是让安全判断建立在可复核的事实上：进程、端点、内容信号、处置动作和存储完整性。

01 / ATTRIBUTION

精确到进程

缓存进程创建时间，减少 PID 复用带来的错误归属；同时保留父进程链与脱敏命令行，帮助识别 Agent、编辑器子进程和脚本运行时。

python.exe · PID 18240
parent: code.exe → chrome.exe
endpoint: api.openai.com/v1/chat
02 / DLP SIGNALS

内容级风险信号

识别 AI 服务端点与常见 API 密钥、私钥、证件号、银行卡、手机号和代码块。风险分可解释，证据保留脱敏，避免审计本身成为密钥泄露源。

secret.openai_key +55
pii.cn_id +40
egress.unknown_destination +15
03 / ACTION

可观察，也可阻断

默认只观察。需要时对达到阈值的请求返回 403，让“是否放行”成为显式策略，而不是事后的猜测。阻断开关默认关闭，避免误伤。

risk ≥ 85 → BLOCK
risk ≥ 45 → ALERT
default → OBSERVE
04 / EVIDENCE

脱敏在前，解密在后

列表与导出只展示脱敏预览。原始正文仅有选择地加密保存，在详情中再次确认后才于当前会话解密。导出的 JSONL 不包含正文。

list/export redacted
raw body AES-256-GCM
master key Windows DPAPI
05 / INTEGRITY

证据链可验证

每条流量写库时，将关键摘要与上一条哈希链接。审计台可随时校验链条是否断裂，为事后取证提供一个廉价的完整性基线。

entry 0421 prev: 9f2c…
sha256(prev + summary)
chain valid

04 / 覆盖边界

我们主动写清楚了
“看不到”的部分。

没有一种用户态方案能看见所有加密流量。一个可信的审计产品，不应该把“代理已启动”宣传成“全部可见”。下面是第一版的真实边界。

在配合路径上可以看见
  • 经过本地代理的 HTTP/HTTPS 请求与响应元数据；系统代理、环境变量代理和手动指定的代理都属于这个范围。
  • 启动时自动继承本机回环 HTTP 代理（如 Clash 的 127.0.0.1:7890）并串联转发；只转发重新加密后的 TLS 字节，上游看不到审计器已解密的正文。
  • 应用信任本地 CA 且未启用证书固定的 TLS 1.2 / 1.3 流量，可还原请求方法、路径、头、正文和响应。
  • 正文保存有体积上限；AI 请求或风险分 ≥ 25 的流量才加密保留原始正文，其他流量保留脱敏预览。
  • 客户端进程 PID、父进程链、脱敏命令行与进程创建时间，用于区分真实发起者与 PID 复用。
  • AI 服务分类、模型名、密钥 / PII / 代码 / 文件引用等规则信号，以及可配置的阻断动作。
不承诺、也看不到
  • 未经过代理的直连流量。忽略系统代理的应用必须用环境变量或后续的透明重定向接入。
  • 证书固定、mTLS、双向证书校验。这些是应用有意建立的安全边界，不被本项目攻破。
  • QUIC / HTTP3 与非 HTTP 协议。第一版不解析，无法给出内容级结论。
  • 应用层端到端加密。没有密钥时，即使流量经过代理也只能看到密文和元数据。
  • Windows 服务 / SYSTEM 会话的完整归因。当前面向登录用户进程，服务账户路径在路线图中。
  • 完整文件读取历史。打开句柄抽样无法证明文件已被读取，也不覆盖已经关闭的句柄。
重要安全边界：不要在日常使用、存有真实凭据的设备上分析疑似恶意软件。受信 CA 会扩大本机可被中间人解密的范围。请在隔离虚拟机 / 快照中处理未知样本，分析结束后移除 CA 并恢复系统代理。

06 / 快速开始

三步接入，
不自动接管系统。

桌面控制台和本地审计台会同时启动。系统代理、根证书与阻断策略都需要显式确认；你可以随时暂停采集或恢复原代理设置。

1

启动 EgressScope

双击可执行文件，或使用 EgressScope.exe --headless 运行无窗口模式。代理默认监听 127.0.0.1:8899，审计台绑定回环地址。

2

确认根证书

在控制台点击“安装根证书”，将公开 CA 加入当前用户信任根。私钥始终留在本机数据目录，不会分发；安装后可随时移除。

3

选择流量入口

开启系统代理，或只给目标 Agent 注入 HTTPS_PROXY 与 NODE_EXTRA_CA_CERTS 等变量。若本机原本通过 Clash 等回环代理（如 127.0.0.1:7890）上网，程序会在启动时自动串联，避免接管后断网。

07 / 隐私设计

审计工具本身，
不应该成为新的泄露面。

数据边界不是靠一句“我们很重视隐私”。它需要落实在密钥位置、导出格式、默认设置和系统变更的撤销路径上。

  • 正文加密存储

    AES-256-GCM 加密请求 / 响应正文；主密钥由当前 Windows 用户的 DPAPI 保护。更换用户或离线拷走数据库都无法直接解密。

  • 脱敏是默认值

    列表、搜索、预览和 JSONL 导出只包含脱敏后的内容与哈希。原始正文需要显式的二次确认才会解密显示，且不回写数据库。

  • 最小化系统变更

    CA 只装当前用户，不自动安装；系统代理修改前备份，检测到 PAC 时拒绝接管；退出时仅在设置仍属于本工具时恢复。

  • 本地回环服务

    Web 审计台只绑定 127.0.0.1，使用每次启动随机生成的会话令牌，校验 Host 并应用严格 CSP。没有云同步，没有外部字体或脚本。
