能力总览

把“有一条连接”变成一次可复核的外发记录

每一项能力都对应本机证据链上的一个环节：从流量入口、内容还原、进程归因，到风险判定与加密留存。审计台可随时校验链条是否完整。

HTTPS 外发可见性

本地代理终止 TLS，还原请求方法、路径、请求头与正文，并记录响应状态与体积。不遵循代理设置的应用不会被假装看见。

TLS 1.2 / 1.3 · HTTP/1.1 · HTTP/2

进程级归因

用客户端临时端口匹配本机 TCP 归属表，缓存 PID 与进程创建时间以减少 PID 复用误判，并保留父进程链与脱敏命令行。

port → pid → parent chain

AI 端点识别

识别主流 AI 服务与本地自建端点，提取模型名与 token 用量，把 AI 外发与普通遥测、下载流量区分开。

category: ai_saas / ai_local / other

敏感数据规则

匹配常见 API 密钥、私钥、证件号、银行卡、手机号、源码块与文件路径引用，形成可解释、可复核的风险分。

secret.openai_key +55 · pii.cn_id +40

加密证据链

每条记录的关键摘要与上一条哈希链接，正文加密保存，列表与导出默认脱敏；可随时校验链条并导出 JSONL 证据。

sha256(prev + summary) → chain valid

文件触达关联（Beta）

抽样近期外发进程打开的文件句柄，并用虚构诱饵文件观察异常触达。只记录路径与时间等元数据，不读取文件内容。

metadata only · content never read
工作原理

用户态本地代理 + 本地 CA + 进程归因

这条路径不需要内核驱动签名，不依赖任何 Agent 的私有数据格式，并且失败模式清晰：应用不配合就看不到，不会把“代理已启动”说成“全部可见”。

STEP 01

应用 / Agent 发起请求

Claude Code、Codex、编辑器插件、SDK 或普通桌面程序发出 HTTPS 请求。

STEP 02

进入本地转发代理

代理只监听 127.0.0.1，通过系统代理或进程环境变量接入，不影响局域网。

STEP 03

本地 CA 终止 TLS

使用当前用户信任的本地 CA 签发站点证书，还原 HTTP 语义后再重新加密转发。

STEP 04

归因到发起进程

客户端端口匹配本机 TCP 表，得到 PID、进程名、父进程链与创建时间。

STEP 05

策略判定与证据留存

端点分类、DLP 规则、风险评分与处置动作，正文加密写入哈希链证据库。

进程流量→ 内容可读→ 是谁发起→ 可验证证据→ 本机审计台

为什么选择本地代理

失败模式清晰、可解释、可撤销。修改系统代理前先备份，退出时恢复；检测到 PAC 脚本时拒绝接管；已有 Clash 等回环代理时自动串联，避免接管后断网。

为什么使用 mitmproxy

不重复造 TLS。成熟的开源代理负责 HTTP/2、证书签发与流式转发，项目把工程精力集中在归因、策略、证据链与产品边界上。

为什么需要本地 CA

还原内容必须经过应用同意。CA 只安装到当前用户信任根且不会自动安装；证书固定、mTLS 与端到端加密不被本项目攻破。

覆盖边界

我们主动写清楚了“看不到”的部分

没有一种用户态方案能看见所有加密流量。一个可信的审计产品，不应该把“代理已启动”宣传成“全部可见”。下面是当前版本的真实边界。

在配合路径上可以看见
  • 经过本地代理的 HTTP/HTTPS 请求与响应元数据；系统代理、环境变量代理和手动指定的代理都属于这个范围。
  • 启动时自动继承本机回环 HTTP 代理（如 Clash 的 127.0.0.1:7890）并串联转发；只转发重新加密后的 TLS 字节，上游看不到审计器已解密的正文。
  • 应用信任本地 CA 且未启用证书固定的 TLS 1.2 / 1.3 流量，可还原请求方法、路径、头、正文和响应。
  • 正文保存有体积上限；AI 请求或风险分 ≥ 25 的流量才加密保留原始正文，其他流量保留脱敏预览。
  • 客户端进程 PID、父进程链、脱敏命令行与进程创建时间，用于区分真实发起者与 PID 复用。
  • AI 服务分类、模型名、密钥 / PII / 代码 / 文件引用等规则信号，以及可配置的阻断动作。
不承诺、也看不到
  • 未经过代理的直连流量。忽略系统代理的应用必须用环境变量或后续的透明重定向接入。
  • 证书固定、mTLS、双向证书校验。这些是应用有意建立的安全边界，不被本项目攻破。
  • QUIC / HTTP3 与非 HTTP 协议。当前版本不解析，无法给出内容级结论。
  • 应用层端到端加密。没有密钥时，即使流量经过代理也只能看到密文和元数据。
  • Windows 服务 / SYSTEM 会话的完整归因。当前面向登录用户进程，服务账户路径在路线图中。
  • 完整文件读取历史。打开句柄抽样无法证明文件已被读取，也不覆盖已经关闭的句柄。
重要安全边界：不要在日常使用、存有真实凭据的设备上分析疑似恶意软件。受信 CA 会扩大本机可被中间人解密的范围。请在隔离虚拟机 / 快照中处理未知样本，分析结束后移除 CA 并恢复系统代理。
断网保护

接管系统代理之后，本机不能失联

这是一个真实存在的失败模式：如果电脑突然断电、程序崩溃或被强制结束，Windows 的系统代理仍会指向 127.0.0.1 上已经停止的端口，浏览器与多数应用会连接失败——和某些 VPN 客户端退出后留下的问题一样。v0.3.0 用四层机制处理它，其中三层不需要你做任何配置。

1

关机 / 注销时优雅恢复

程序注册了 Windows 会话结束通知（消息窗口的 WM_QUERYENDSESSION / WM_ENDSESSION，控制台构建同时挂 SetConsoleCtrlHandler）。你点关机、重启或注销时，系统会先通知我们；程序在会话真正结束前把系统代理还原为启用前的备份值并刷新 WinINET，因此下一次开机不会继承一个指向已停止端口的代理。

AUTOMATIC · v0.3.0 · 无需配置
2

启动时校正

程序启动会检查系统代理是否仍指向本工具：端口变了就重新指向新的监听端口；本地代理没能启动，就立刻恢复原始设置，不把机器留在断网状态。配合默认开启的开机自启，登录后这条链路会重新建立。

AUTOMATIC · 无需配置
3

独立看门狗任务

启用系统代理时的确认对话框默认勾选这一项，一键注册一个仅当前用户的计划任务：登录时以及每 2 分钟检查一次，如果系统代理仍指向已停止的回环端口，等待 30 秒宽限后恢复备份的原始值、刷新 WinINET 设置，然后自动停用任务，避免无意义的重复运行。

默认勾选 · 每用户 · 不需要管理员
4

手动恢复

桌面控制台提供“恢复系统代理”，也可以直接运行命令行恢复；极端情况下还能在 Windows 设置的网络代理页手动关闭。备份文件被保留，直到恢复成功。

MANUAL · 始终可用

默认行为

安装即观察，改动即时生效

v0.3.0 把“需要逐项勾选才能开始审计”改成了默认就位：观察能力开箱开启，配置改动不需要重启进程，登录自启与关机恢复形成闭环。会中断请求或写入文件的两项能力仍然保留显式确认。

默认开启的观察能力

流量采集、AI 端点识别、敏感数据规则与文件句柄抽样默认全部开启，装完就能看到完整证据链，不必先研究一遍开关。两项例外仍需你显式打开：风险阻断会直接返回 403 中断请求，Canary 诱饵会往 Documents 写入含虚构凭据的文件。

capture · ai endpoints · dlp rules · file sampling = on

配置热更新，无需重启

控制台开关、Web 审计台开关，或直接编辑 %LOCALAPPDATA%\EgressScope\config.json，都会在 2 秒内被运行中的进程采纳。上游代理变更会自动重连并重新校正系统代理，抽样间隔、保留期与自启开关即时生效，不需要等待重启窗口。

config.json → mtime poll (2s) → live settings

默认开机自启，可随时撤销

启用系统代理后写入当前用户的 Run 键，登录时最小化启动，与关机 / 注销优雅恢复配合形成闭环，不会出现“开机后代理没人接管”的空档。控制台一键关闭，或运行 --disable-autostart；撤销时只删除我们自己写入的值，不动其他程序的自启项。

HKCU\...\CurrentVersion\Run\EgressScope
你可以确认热更新已经完成：接口与控制台会返回 config_reload（完成时间与本次生效的键名），不需要靠猜。监听端口、Web 端口与证书目录这类需要重建进程的字段不在热更新范围内，改完需要重启一次，控制台会明确提示。

快速开始

三步接入，不自动接管系统

桌面控制台与本机审计台会同时启动，采集、AI 端点识别、敏感数据规则与文件句柄抽样默认开启。真正改动系统的三件事——根证书、系统代理与风险阻断——仍然需要你显式确认；所有设置改动即时生效，不需要重启进程。

1

启动 EgressScope

双击可执行文件，或用 EgressScope.exe --headless 运行无窗口模式。代理默认监听 127.0.0.1:8899，审计台绑定回环地址并带随机访问令牌。首次启动会写入当前用户 Run 键实现登录自启，可在控制台一键关闭。

2

确认根证书

在控制台点击“安装根证书”，把公开 CA 加入当前用户信任根。私钥始终留在本机数据目录，不会分发；安装后可随时移除。

3

选择流量入口

开启系统代理（确认对话框默认勾选断网保护看门狗），或只给目标 Agent 注入环境变量。若本机原本通过 Clash 等回环代理上网，程序会在启动或热更新时自动串联，避免接管后断网。

隐私与安全设计

审计工具本身不应该成为新的泄露面

数据边界不能只靠一句“我们很重视隐私”。它需要落实在密钥位置、导出格式、默认设置与系统变更的撤销路径上。

  • 正文加密存储

    AES-256-GCM 加密请求与响应正文，主密钥由当前 Windows 用户的 DPAPI 保护。更换用户或离线拷走数据库都无法直接解密。

  • 脱敏是默认值

    列表、搜索、预览与 JSONL 导出只包含脱敏后的内容与哈希。原始正文需要显式二次确认才会在当前会话解密，且不回写数据库。

  • 最小化系统变更

    CA 只装当前用户且不自动安装；系统代理修改前先备份，检测到 PAC 时拒绝接管；退出时仅在设置仍属于本工具时恢复。

  • 本地回环服务

    Web 审计台只绑定 127.0.0.1，使用每次启动随机生成的会话令牌，校验 Host 头并应用严格 CSP。没有云同步、外部字体或第三方脚本。

常见问题

关于能力边界与使用前提

下面这些问题决定了它是否适合你的场景。答案与本产品的实际实现一致，不做超出能力的承诺。

提交问题或反馈
01电脑突然关机或程序崩溃后，本机还能上网吗？
系统代理仍指向已停止的回环端口时，浏览器与多数应用会连接失败——这是真实存在的失败模式。v0.3.0 提供四层处理：关机、重启或注销时收到 Windows 会话结束通知后立刻恢复原始代理；启动时校正过期设置；启用系统代理时默认勾选的每用户计划任务看门狗在登录后自动恢复；以及 EgressScope.exe --restore-proxy 手动恢复。直接拔电源、内核崩溃或强制结束进程时收不到会话结束通知，此时恢复发生在下一次登录后。
02它是杀毒软件或 EDR 吗？
不是。EgressScope 只做外发流量的可见性、归因、策略判定与证据留存，不做恶意代码检测，也不提供阻断未知威胁的能力。风险分是启发式信号，用于辅助人工判断，不能直接当作处置结论。
03它会读取我的聊天记录吗？
只有在你启用系统代理或注入环境变量、并信任本地 CA 之后，经过代理的 HTTPS 正文才会被解析。列表与导出默认脱敏，原始正文需要在详情里再次确认才解密显示，且不回写数据库。它不读取任何 Agent 的本地会话文件。
04能看见所有加密流量吗？
不能。证书固定、mTLS、QUIC / HTTP3、应用层端到端加密，以及完全绕过代理的直连流量都在覆盖边界之外。本产品不承诺、也不会尝试攻破这些机制。详见覆盖边界一节。
05审计数据会上传到云端吗？
不会。证据保存在本机 SQLite，正文用 AES-256-GCM 加密，主密钥由当前用户的 DPAPI 保护。Web 审计台只绑定回环地址，使用每次启动随机生成的令牌，页面不含外部字体、脚本或统计代码。
06需要管理员权限吗？
不需要。CA 只安装到当前用户信任根，系统代理是每用户设置，断网保护看门狗与开机自启也都写在当前用户下（每用户计划任务 + Run 键），可随时逐项撤销。这也是它的边界：Windows 服务与 SYSTEM 会话的完整归因不在当前版本范围内。
07已经在用 Clash 或其他本地代理怎么办？
启动时会自动继承本机回环 HTTP 代理（例如 127.0.0.1:7890）并串联转发，避免接管后断网。上游只看到重新加密后的 TLS 字节。带用户名密码的上游、PAC 脚本与 SOCKS 目前不支持，这些场景请改用单 Agent 环境变量接入。
08对性能与磁盘有多大影响？
代理运行在用户态、只走本机回环。正文保存有单条体积上限，只有 AI 请求或风险分达到阈值的流量才加密保留原文；证据默认保留 7 天，可在设置中调整，也可以一键清空。
09支持哪些操作系统？
Windows 10 / 11 的 x64 与 ARM64 是功能完整的桌面版本，含系统代理接入、CA 一键安装与断网保护。macOS 与 Linux 提供同一套审计引擎与本机 Web 审计台，代理与 CA 需要手动配置；macOS 在非 root 下无法读取 TCP 归属表，会降级为不含 PID 的记录。
10可以用它审计别人的设备吗？
只应用于你拥有或已获得明确书面授权的设备，未经授权拦截他人流量可能违法。也不要在存有真实凭据的日常主机上分析疑似恶意软件：受信 CA 会扩大本机可被中间人解密的范围，请在隔离虚拟机或快照中进行，结束后移除 CA。
11项目是开源的吗？许可是什么？
源码与构建流水线公开在 GitHub，可自行审计与复现构建。仓库当前未附带标准开源许可证，使用即表示你理解并接受 README 中的授权、安全与覆盖边界声明。
12修改设置需要重启程序吗？开机自启能关吗？
采集开关、阻断阈值、保留期、文件句柄抽样、上游代理与开机自启都是热更新：控制台改完立即生效，直接编辑 config.json 也会在 2 秒内被运行中的进程采纳，接口会返回 config_reload 告诉你哪些键已生效；上游代理变更会自动重连并重新校正系统代理。只有监听端口、Web 端口与证书目录这类需要重建进程的字段要重启一次。开机自启默认开启，写入当前用户 Run 键，可在控制台一键关闭或运行 --disable-autostart。
