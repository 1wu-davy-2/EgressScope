# EgressScope 执行计划与状态

> 状态快照：v0.4.0，文档更新于 2026-10-25。
> 这份文档把 [`PLAN.md`](../PLAN.md) 的研究计划映射到实际交付，并明确“已实现 / 部分实现 / 未实现”。计划项不代表已有能力，也不承诺发布日期。

## 1. 计划口径

项目存在两套容易混淆的编号，阅读时先区分：

### 1.1 PLAN.md 的原始阶段

| 阶段 | 原始目标 | 计划退出条件 |
| --- | --- | --- |
| P0 可行性验证 | 验证代理 + CA + PID 归因 + 内容审计 + 文件读取关联在 Windows 上可行 | 目标 Agent 正文覆盖 ≥ 70%；归因 ≥ 99%；失效恢复无残留；形成兼容矩阵与 Go/No-Go 结论 |
| P1a 网络与内容审计 MVP | 单用户、本地、AI 应用内容审计 + 全应用元数据 + 进程归因 | 3 类 Agent 端到端可用；密钥/代码外发可检出；24h 运行；断网恢复；无明文正文落盘 |
| P1b 文件读取关联 | SACL/4663、敏感目录、Canary、“读取 → 外发”关联 | 能生成“文件路径 → 进程 → 目标 → 时间”的证据链；开销可控 |
| P2 覆盖与阻断 | WFP/WinDivert、服务/机器级、ETW、MCP/Agent 数据、阻断审批 | 目标应用/服务覆盖提升；阻断可回滚；驱动签名与稳定性通过 |
| P3 产品化 | 安装器、签名、自动更新、性能与安全加固、团队/SIEM、macOS/Linux | 干净机安装成功率高；升级/回滚/卸载可靠；安全评审通过 |

原始计划是立项前的调研底稿，包含“建议”“待验证”和假设，不能直接当作产品承诺。

### 1.2 实际执行轮次

v0.4.0 的交付按风险与依赖重新排序，实际执行轮次为：

1. **P0：可用性与恢复**：Windows x64 per-user 安装包、固定安装目录、自动更新、自启/看门狗自愈、独立 `--restore-proxy`、关机实验工具与契约测试。
2. **P1：可见性**：五级流量可见性、旧库迁移、只读连接表/QUIC/DNS 旁路观测。
3. **P2：桌面常驻**：Windows 托盘、关闭隐藏、暂停/恢复、退出恢复代理。
4. **横切工作**：测试、CI、官网、README、CHANGELOG、许可协议与本文档包。

这轮编号与 PLAN 的阶段编号不是一一对应；下文的“交付状态”以实际能力为准。

| 风险 | 影响 | 当前缓解 | 残余风险 |

## 6. 决策记录

### ADR-001：基线采用本地代理 + 本地 CA + 进程归因

- **决策**：v0.4.0 不引入内核驱动，不实现 WFP/WinDivert 透明重定向。
- **理由**：无需驱动签名，部署与回滚成本低；内容、归因、策略、证据可以快速闭环；用户能理解并撤销系统变更。
- **代价**：只覆盖遵循代理并信任 CA 的应用；直连、QUIC、服务和固定证书应用只能看到元数据或候选。
- **后续**：透明重定向必须单独完成驱动签名、兼容性、误伤与回滚评估，不能降低现有诚实边界。

### ADR-002：采用五级可见性，而不是“成功/失败”二分

- **决策**：每条流量标记 `full` / `partial` / `metadata` / `blocked` / `error`，附中文原因。
- **理由**：审计产品最大的误导是把“看到连接”写成“看到内容”；五级能明确区分隧道失败、握手失败、WebSocket、正文缺失与错误。
- **代价**：旧库需要迁移；UI、API 与导出都要携带新字段。

### ADR-003：旁路观测只检测，不接管

- **决策**：连接表观测只记录直连/QUIC/DNS 候选，不重定向、不拦截、不解密。
- **理由**：在不引入驱动和额外拦截风险的前提下暴露“代理没看到”的缺口；候选可能误报，不能当内容证据。
- **代价**：无法阻止应用绕过代理；短连接可能被 15 秒采样遗漏。

### ADR-004：默认观察，系统变更显式确认

- **决策**：采集、AI 识别、DLP、文件句柄抽样、旁路观测默认开启；CA 安装、系统代理、阻断、Canary 需显式开启/确认。
- **理由**：装完即可产生证据，同时把影响系统信任与网络路径的操作留给用户确认。
- **代价**：默认行为仍会接触本地元数据；部署前必须完成告知与授权。

### ADR-005：Windows x64 per-user 安装包与 SHA-256 更新

- **决策**：固定安装目录、无需管理员、仅 Windows x64 提供安装包与自动更新。
- **理由**：避免管理员权限与目录漂移，更新器能可靠找到安装位置；per-user 影响面小。
- **代价**：Windows ARM64 无安装包；自动更新仍依赖 GitHub 网络；SHA-256 不等于发布者身份验证。

### ADR-006：采用 PolyForm Noncommercial 1.0.0

- **决策**：允许下载、使用、修改与非商业分发，禁止商业用途；分发保留许可证与 Required Notice。
- **理由**：满足“可下载使用但禁止商用”的产品要求。
- **代价**：这是 source-available，不是 OSI 开源；商业使用需要书面授权；既有 v0.4.0 二进制早于该变更。

### ADR-007：文档以 `docs/` 包提交，而不是重复的压缩包

- **决策**：在仓库中维护可阅读、可 diff 的 `docs/` 文档包，根目录 README/PLAN/CHANGELOG 继续作为权威来源。
- **理由**：压缩包不可审阅、不可增量维护，容易与代码脱节；Git 历史本身已提供归档。
- **代价**：需要在发布时同步多份文档与版本号。

### ADR-008：官网拆分为能力首页与技术说明页

- **决策**：`web/intro.html` 保持能力优先的短文案；技术实现、数据路径与边界放到 `web/tech.html`。
- **理由**：降低首页阅读负担，同时保留完整技术说明供评估者查阅。
- **代价**：两个页面都需要维护 i18n、ARIA、JSON-LD 与版本门禁。

## 7. 后续路线

以下路线来自 README，是实现方向而不是承诺。每项进入开发前都需要明确威胁模型、验收标准与回滚方案。

### P1：扩大入口，不放松诚实边界

| 方向 | 目标 | 前置条件 |
| --- | --- | --- |
| WFP / WinDivert 透明重定向 | 覆盖不遵循系统代理的应用 | 驱动签名、兼容性矩阵、fail-open、误伤评估、卸载/回滚 |
| Agent / MCP 清单与会话导入 | 补充代理层看不到的 Agent 私有数据 | 适配器版本化、隐私边界、只读导入 |
| SIEM / OpenTelemetry 导出 | 接入企业可观测与告警 | 导出签名、可信时间戳、脱敏与访问控制 |
| 规则包签名与策略分发 | 可验证的策略来源 | 签名格式、版本兼容、回滚 |
| 代理链路健康检查与覆盖诊断 | 更快解释“为什么看不到” | 诊断项不收集正文 |

### P2：系统与文件视角

- ETW / SACL / USN / 文件系统微过滤驱动的完整读取审计。
- Windows 服务 / SYSTEM 会话的进程归因与机器级部署。
- 与网络时间线关联的文件读取证据视图。
- 企业级留存、告警与只读审计员角色。
- macOS / Linux 的代理接管、CA 安装、托盘与开机自启等价能力。
- 关机实验工具的虚拟机自动重启/注销编排。

### 每项功能的进入与退出条件

- **进入**：有明确用户问题、威胁模型、失败模式与撤销路径；不把未验证假设写成能力。
- **退出**：有自动化测试或可复现验收记录；文档写明覆盖与缺口；CI/发布流程可重复。
- **发布**：版本号、CHANGELOG、README、站点与测试断言同步；不发布未通过的构建。

## 8. 执行规则

1. **先验证，再承诺。** 没有测试、CI 或可复现记录的能力，只能写成“计划”或“未实现”。
2. **诚实边界优先于功能数量。** `metadata` 不写成正文，候选不写成证据，检测不写成阻断。
3. **系统变更必须可撤销。** 新增 CA、代理、自启、计划任务、驱动或服务时，同时设计恢复与卸载路径。
4. **发布门禁不可绕过。** 相关测试、站点门禁、版本同步与 CHANGELOG 小节缺一不可。
5. **授权优先。** 仅审计自有或已获明确授权的设备；不提供隐蔽监控或规避安全软件的能力。
6. **文档随代码更新。** 功能、测试、发布流程变化时，在同一次改动中更新对应文档。
