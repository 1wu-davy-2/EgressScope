# EgressScope 设计说明

> 状态：与 v0.4.0 实现同步，文档更新于 2026-10-25。
> 读者：架构评审、安全评审、贡献者与集成者。
> 相关文档：[文档中心](README.md) · [执行计划](execution-plan.md) · [测试与发布](testing-and-release.md) · [README](../README.md)

## 1. 问题与目标

EgressScope 是一个以 Windows 为主的本机数据外发审计工具。它把本地 HTTP/HTTPS 转发代理、本地 CA、进程归因、内容策略与本地证据库串成一条链，回答：

> **是谁，在什么时候，把什么内容，发到了哪里？**

目标：

1. **看得见**：按进程展示连接、目标、请求摘要、风险与可见性等级。
2. **认得准**：把连接归因到 PID、可执行文件与父进程链，而不是只显示“来自本机”。
3. **判得了**：结合目标、路径、正文、敏感数据与进程上下文给出可解释的风险信号。
4. **留得住**：正文按需加密，元数据可检索，导出脱敏，并提供可校验的哈希链。
5. **不添乱**：系统代理在正常退出、关机、注销与异常退出后都有恢复路径；不破坏已有 Clash/VPN 链路。
6. **说清楚**：看不到的内容必须明确降级，不能把元数据伪装成完整正文。

典型场景：

- AI Agent、IDE 插件或脚本把源代码、`.env`、密钥、客户数据发往外部 API。
- 应用连接到未批准的 AI 厂商、中转站或未知域名。
- 需要判断一次外发由哪个进程、哪条父进程链发起。
- 需要区分“代理看到了正文”“只看到连接元数据”“连接根本没经过代理”。

## 2. 非目标与威胁模型

### 2.1 非目标

- 不是 EDR 或杀毒软件，不承诺清除恶意软件、驱动或内核级威胁。
- 不是全流量 DPI，不解析所有私有协议。
- 不是隐蔽监控软件，不提供隐藏运行、规避用户发现或绕过安全软件的能力。
- 不是“万能解密器”，不绕过证书固定、mTLS、应用层端到端加密或恶意程序自定义加密。
- 不默认长期保存所有应用的完整正文。
- 不在 v0.4.0 做 WFP/WinDivert 透明重定向、机器级服务部署或多租户远程控制。

### 2.2 覆盖与不覆盖

| 范围 | 说明 |
| --- | --- |
| 覆盖 | 明确授权设备上的用户态应用；遵循系统代理或环境变量代理、且信任本地 CA 的 HTTP/HTTPS 流量；登录用户可观察的直连/QUIC/DNS 元数据候选 |
| 部分覆盖 | 证书固定、mTLS、WebSocket 消息、流式响应、Windows 服务/SYSTEM 会话、Linux/macOS 的 PID 归因 |
| 不覆盖 | 应用层 E2EE、QUIC/HTTP3 正文、恶意程序私有加密、未接入审计器的 TUN/VPN 流量、被篡改的审计器本身 |

审计是“检测与取证”层，不是“隔离”层。对高风险或疑似恶意软件场景，应配合应用管控、防火墙出口白名单、独立用户/虚拟机与网络隔离。

## 3. 设计原则

1. **诚实可见性优先。** 只有真正读到可读响应才标记为“完整”；隧道失败、握手失败、正文缺失、WebSocket 都必须降级并写明原因。
2. **本地优先。** 默认无云端上报、无外部字体/脚本/遥测；审计数据、CA、配置与证据保存在本机。
3. **最小权限与显式授权。** CA 安装与系统代理启用只在桌面控制窗口发生，并需要用户确认；Canary 默认关闭，可在控制台或审计台设置中显式开启（开启时会写入虚构凭据文件）；Web 审计台没有安装 CA 或接管系统代理的接口。
4. **系统变更可撤销。** 恢复原系统代理、移除 CA、关闭开机自启、移除看门狗、清空数据与卸载都有对应路径。
5. **网络故障 fail-open。** 审计器异常时应尽量恢复用户网络，而不是把机器留在“指向已停止代理”的状态。
6. **内容与元数据分层。** 正文、连接元数据、旁路候选是三种不同证据；不把候选当结论。
7. **基线不依赖内核驱动。** 先用本地代理 + 本地 CA + 进程归因跑通内容、归因、策略与证据闭环；透明重定向留到后续评估。
8. **默认观察、谨慎处置。** 采集、AI 识别、DLP、文件句柄抽样与旁路观测默认开启；风险阻断、Canary、CA 安装与系统代理接管需显式开启。
9. **证据有边界。** 哈希链提供篡改可见性基线，但不是外部公证；拥有完整数据库写权限的攻击者仍可能重写整条链。

## 4. 总体架构

```text
AI Agent / 编辑器 / SDK / 普通桌面应用
        │                                   │
        │ 遵循代理                           │ 忽略代理 / QUIC / DNS
        ▼                                   ▼
HTTP/HTTPS 本地转发代理              只读连接表观测（15s）
127.0.0.1:8899                       + Windows DNS 解析缓存
        │                                   │
        ▼                                   ▼
TLS 终止（本地 CA，仅应用信任时）     直连 / QUIC / DNS 候选
        │                            （仅元数据，检测不重定向）
        ▼
HTTP 语义 / 方法 / 路径 / 正文 / 流式元数据
        │
        ▼
可选上行链路（自动继承回环代理 / 手动指定）
        │
        ▼
进程归因（客户端端口 → 本机 TCP 表 → PID → 父进程链）
        │
        ▼
可见性分级（完整 / 部分 / 仅元数据 / 已阻断 / 错误）
        │
        ▼
策略引擎（AI 端点分类、DLP 规则、风险评分、处置）
        │
        ▼
SQLite（WAL）＋ AES-GCM 证据正文＋ SHA-256 审计链
        │
        ▼
本机 Web 审计台 + 桌面控制台 / Windows 托盘
```

两条路径并列而非互相替代：

- **代理路径**：负责可终止 TLS 的 HTTP/HTTPS 正文、归因、策略与阻断。
- **旁路观测（Beta）**：只读本机连接表与 Windows DNS 解析缓存，提示“代理没看到”的直连、QUIC 与 DNS 目标；不重定向、不抓包、不解密。

## 6. 关键设计

### 6.1 接入方式与信任边界

支持两种用户态接入：

1. **系统代理（Windows）**：写入当前用户 WinINet 代理设置，只影响遵循系统代理的应用。启用前保存原值，正常退出、关机/注销、启动校准、看门狗与手动命令共同负责恢复。
2. **Agent 环境变量**：生成 `HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY` / `NO_PROXY` 与 CA 路径脚本（Windows 为 `.cmd`，Linux/macOS 为 `.sh`），只影响当前终端或显式注入的进程。

本地 CA 只在应用信任它且没有证书固定/mTLS 时才能终止 TLS。对未知应用、服务或高风险样本，优先使用单 Agent 环境变量，避免全局代理与受信 CA 的影响。

**上行链路**：可自动继承当前生效的回环 HTTP/HTTPS 系统代理（不继承 PAC、非回环地址或自身端口），也可手动指定。上游只收到目标主机与重新加密的 TLS 字节，不会收到已解密正文；若上游本身是终止 TLS 的企业代理，则属于另一层信任边界。不支持代理认证、PAC 自动发现与 SOCKS 上游。

### 6.2 进程归因

Windows 主路径：

1. 代理在客户端连接时取得源地址 `127.0.0.1:<临时端口>`。
2. 查询本机 TCP 归属表，匹配该客户端端口到代理端口的连接。
3. 取得 owning PID，并结合进程启动时间避免 PID 复用。
4. 构建父进程链，记录进程名、路径、应用类型与脱敏后的命令行。
5. 对 HTTP/2 多路复用连接，同一条 TCP 连接上的流共用归因。

限制：

- 如果客户端先经过另一个本地代理再到 EgressScope，看到的可能是上游代理 PID。
- UWP、服务宿主或权限受限进程可能只能得到 broker PID 或低置信度归因。
- Linux 依赖 `/proc/net/tcp`；macOS 非 root 无法读取系统 TCP 归属表，PID 归因会降级。
- 归因失败时保留连接元数据，不凭空生成进程身份。

### 6.3 可见性分级

每条流量带 `visibility` 与中文 `visibility_reason`。等级描述“这次记录看到了多少内容”，不是对目标安全性的判断。

| 等级 | 界面显示 | 含义 | 典型场景 |
| --- | --- | --- | --- |
| `full` | 完整 | 请求/响应结构可读，正文按策略完整保留 | 应用信任本地 CA、TLS 正常终止、响应正文未超限 |
| `partial` | 部分 | 连接可读，但内容不完整 | WebSocket 消息不持久化；正文流式/超限/缺失；请求正文不完整 |
| `metadata` | 仅元数据 | 只有连接元数据，没有可读正文 | CONNECT 隧道失败；TLS 握手失败；客户端 TLS 未被终止 |
| `blocked` | 已拦截 | 策略在本地拒绝转发 | 风险达到阻断阈值，返回 `403 egress_policy_blocked` |
| `error` | 错误 | 代理或上游错误，未获得响应 | 上游连接失败、代理异常、响应前错误 |

不变量：

- 只有真正读到可读响应才标记 `full`。
- `metadata` 不是“没有发生”，原因中会写明证书固定、mTLS 或客户端拒绝本地 CA 等可能性。
- 原因文本会脱敏并截断，避免把错误信息中的凭据写入证据库。
- 旧库升级时增加可见性列，历史流量迁移为 `partial` 并标注“升级前的历史记录未做可见性分级”。

### 6.4 策略与风险

- 识别常见云端 AI 服务与本地模型端点（如 Ollama、LM Studio）。
- 对未知主机结合路径与 JSON 结构判断为 AI 候选端点，不强行冒充已知厂商。
- 规则覆盖密钥、PII、凭据赋值、敏感环境变量、代码/文件引用、上传体积与未知外发目标。
- 风险分为 0–100 的启发式信号；阻断默认关闭，默认阈值 85。
- 开启阻断后，达到阈值的请求在本地返回 `403 egress_policy_blocked`，证据标记为 `blocked`。
- 响应侧发现标记为 `direction=response`，不计入请求外发风险；列表与导出默认不包含响应原文。

阻断是“本地拒绝转发”，不是网络层防火墙；应用仍可能改用直连或自定义协议。

### 6.5 证据存储

- SQLite 使用 WAL 模式；流量、发现、文件事件、旁路事件、Canary、审计链与元数据分表存储。
- 仅对 AI 流量、风险分 ≥ 25 或存在发现的请求按策略保存正文；默认正文上限 2 MB，流式阈值 `3m`。
- 正文使用 AES-256-GCM；主密钥在 Windows 上由 DPAPI 保护，非 Windows 上退化为文件权限保护。换用户账户或搬走数据库后，原文不可解密。
- 审计链把每条流量的摘要与上一条哈希链接；可验证完整性，但不是外部公证或不可篡改存储。
- 默认保留期 7 天；导出 JSONL 带清单，列表与导出使用脱敏预览。明文只在详情中显式解密，不写回数据库。
- 配置、CA、证据和日志位于 `%LOCALAPPDATA%\EgressScope\data`（可用 `--home` 或 `EGRESSSCOPE_HOME` 覆盖）。

### 6.6 代理失效保护

Windows 上共有四层恢复，前三层不需要用户执行命令：

1. **关机/注销优雅恢复**：在独立消息线程创建隐藏的顶层窗口，处理 `WM_QUERYENDSESSION` / `WM_ENDSESSION`；控制台构建同时处理 `CTRL_LOGOFF_EVENT` / `CTRL_SHUTDOWN_EVENT`。恢复期间调用 `ShutdownBlockReasonCreate`，写回原代理并刷新 WinINet。
2. **启动校准**：代理成功启动后检查代理备份；若系统代理仍指向上一实例端口，改指当前监听端口；新代理启动失败时立即恢复原设置。
3. **断网保护看门狗**：启用系统代理时默认注册当前用户计划任务，登录时与每 2 分钟检查；回环代理端口停止监听超过等待窗口后恢复原始代理并停用自身。
4. **手动恢复**：控制窗口按钮、`--restore-proxy`、`--recover-proxy`、安装版开始菜单的“恢复系统代理”，以及 Windows 设置中的手动关闭代理。

另有**集成自愈**：启动时与每 10 分钟检查当前用户 Run 键和看门狗任务，在程序被移动、覆盖升级或任务丢失后重新指向当前可执行文件。可用 `--repair-integrations` 手动触发。

边界：直接断电、蓝屏、强制结束进程不会收到会话结束消息；恢复退化为下一次登录后的启动校准与看门狗。组策略禁用计划任务、注册表权限不足或数据目录被清空时，自愈可能失败，需要手动恢复。

### 6.7 配置热更新

运行中的进程按配置文件内容摘要检测变更，只采纳 `EDITABLE_KEYS` 中的键：

- 采集、阻断与阈值、正文保存、保留期清理、文件守护、Canary、上游代理与自动继承、开机自启、更新检查、旁路观测。
- 上游代理变更会重连本地代理并重新校准系统代理。
- 暂停采集（`capture_enabled=false`）停止写入新证据并暂停旁路观测，但不会移除 CA 或恢复系统代理。

必须重启的字段：监听端口、Web 端口、证书目录、`insecure_upstream`、`upstream_ca`。非法 JSON、文件暂时不可读或被删除时保留当前设置，并通过 `config_reload` 暴露状态。

### 6.8 旁路观测（Beta）

每 15 秒通过 psutil 读取本机连接表：

| 类型 | 条件 | 记录 |
| --- | --- | --- |
| `direct_tcp` | 公网远端 TCP 80 / 443 / 8080 / 8443 | 时间、PID、进程、远端地址、可选域名 |
| `quic` | 公网远端 UDP 443 | 同上，标记为 QUIC 候选 |
| `dns` | 公网远端 TCP/UDP 53、TCP 853 | 目标与进程；不记录查询内容 |

- Windows 读取 DNS 解析缓存补全 IP→域名；Linux/macOS 不补全。
- 10 分钟去重；单次扫描最多 50 条、单日最多 5000 条；暂停采集时同步暂停。
- 只检测，不重定向、不拦截、不注入、不安装驱动、不解密 QUIC。
- 候选可能来自上游代理、非 HTTP 协议、短连接或共享 PID，不能单独作为数据外发结论。

### 6.9 文件触达与 Canary

- 文件守护对打开句柄抽样（Beta），默认开启；只记录路径、时间、进程等元数据，从不读取文件内容，也不覆盖已关闭句柄。
- 默认观察 Documents、Desktop、Downloads、`.ssh`、`.aws` 等存在目录。
- Canary 诱饵默认关闭；启用后在指定目录写入含虚构凭据的文件，读取事件用于高优先级提示。
- 文件触达不能证明一次读取已经发生，也不能关联“读取 → 加密上传”的完整数据流；SACL/4663 与 ETW/USN 仍在路线图中。

### 6.10 桌面、托盘与本地 Web

- Tkinter 桌面控制窗口负责 CA、系统代理、开机自启、暂停与导出等系统级操作。
- Windows 托盘由 pystray + Pillow 提供；关闭窗口默认隐藏，托盘菜单可打开控制台/审计台、暂停或恢复审计、退出并恢复系统代理。
- “暂停审计”只停止写入新证据与旁路观测，不移除 CA、不恢复系统代理；“关闭窗口”也不等于退出。
- Web 审计台只监听 `127.0.0.1`，每次启动生成随机令牌，校验 Host，使用 CSP、`no-store`，拒绝非回环 Host。
- UI 与 API 面向本机单用户审计，不提供多租户或远程访问。

### 6.11 安装与更新

- Windows x64 使用 per-user Inno Setup 安装包：无需管理员权限，固定安装到 `%LOCALAPPDATA%\Programs\EgressScope`，开始菜单提供主程序与 `--restore-proxy` 快捷方式，桌面快捷方式可选。
- 卸载时移除开机自启并恢复系统代理；静默卸载保留审计数据，交互式卸载询问是否删除数据目录。
- 更新检查默认开启：启动 30 秒后检查一次，之后每 24 小时一次，缓存 6 小时；手动检查强制刷新。
- 自动安装仅 Windows x64，要求发布中存在安装包与 `.sha256` 或 `SHA256SUMS.txt`；只接受 HTTPS 与 GitHub 控制域名，校验失败即删除下载文件。
- SHA-256 只证明下载内容与发布页一致，不等同于代码签名或发布者身份验证。当前 EXE 与安装包默认未签名，除非仓库配置签名密钥。

## 7. 安全与隐私

- **授权边界**：仅审计自有或已获明确书面授权的设备；安装本地 CA 会扩大本机可被中间人解密的范围。
- **可疑样本**：不要在存有真实凭据的日常主机上安装受信 CA 分析未知恶意软件；使用隔离虚拟机/快照与独立分析 CA，结束后移除。
- **CA 私钥**：只保存在本机数据目录，不导出、不写入日志；移除 CA 会撤销当前用户证书存储中的信任，数据目录中的 CA 文件随数据目录清理或卸载删除策略处理。
- **本地 API**：回环绑定、随机令牌、Host 校验、CSP 与 `no-store`；系统级操作不经 Web 触发。
- **脱敏**：请求头、查询参数、JSON 字段与已知密钥模式在预览/导出中脱敏；错误原因也会脱敏后入库。
- **最小采集**：默认只对 AI 流量或风险 ≥ 25 的请求保存正文；响应发现不计入请求外发风险。
- **不上报**：无云端遥测；更新检查只访问 GitHub Releases 公开接口，不上传审计数据、主机名或本地标识。
- **更新校验**：只接受 HTTPS 与 GitHub 域名，必须匹配 SHA-256；但当前构建未签名，SHA-256 不是发布者身份验证。
- **文件内容**：文件守护从不读取内容；Canary 文件的内容是虚构凭据。
- **证据局限**：哈希链不是外部公证；有数据库写权限的攻击者仍可能重写整条链。

## 8. 已知设计边界

- 不解析、不解密 QUIC / HTTP3；只记录 UDP 443 候选元数据；没有 WFP / WinDivert 透明重定向。
- 不绕过证书固定、mTLS、E2EE；握手失败只记录 `metadata` 与原因。
- Windows 服务 / SYSTEM 进程覆盖不完整；当前代理与归因面向登录用户。
- 文件触达只记录句柄元数据，不读取内容，也不提供 SACL/4663 或完整读取历史。
- 流式响应正文不持久化；WebSocket 消息不持久化，只能标记为 `partial`。
- 上游链路支持热更新，但不支持代理认证、PAC 自动发现、SOCKS 上游；端口与证书目录改动需重启。
- Linux / macOS 不提供系统代理接管、一键 CA、托盘或开机自启；macOS 非 root 下 PID 归因降级。
- 旁路观测每 15 秒采样，短连接可能遗漏；域名补全仅限 Windows 解析缓存；候选可能误报。
- 关机/注销恢复没有在 CI 或真实虚拟机执行真实重启验证；只有契约测试与实验脚本。
- Windows ARM64 的 Tk 控制台与托盘未做实机 UI 验收；托盘只在 Windows x64 做过人工冒烟。
- 单文件可执行包较大，首次启动有解压开销。
- UI 与 API 面向本机单用户审计，不提供远程访问或多租户。

## 9. 后续方向

以下方向来自 README 路线图，属于计划而非 v0.4.0 能力：

- **扩大入口**：WFP / WinDivert 透明重定向、Agent/MCP 清单与会话导入、代理链路健康检查。
- **增强证据**：SIEM / OpenTelemetry 导出、导出签名与可信时间戳、签名规则包。
- **系统与文件视角**：ETW / SACL / USN / 文件系统微过滤、服务/SYSTEM 归因、读取与外发时间线关联。
- **平台对等**：macOS / Linux 的系统代理接管、CA 安装、托盘与开机自启。
- **企业能力**：机器级部署、留存策略、告警、只读审计员角色。

任何扩展都必须保留现有诚实边界：能看内容时看内容，不能看内容时只报告元数据/候选，不承诺绕过加密或系统安全控制。
